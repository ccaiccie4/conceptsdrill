Did You Know That?

BGP AIGP: carrying an IGP-like distance across a controlled multi-AS domain

Why this is hard to remember. Ordinary BGP knows policy and AS hops; the IGP knows detailed internal cost only inside one routing domain. AIGP bridges that gap for contiguous ASes under common administration by carrying an accumulated metric without leaking the full IGP.

Mechanics. AIGP is an optional non-transitive path attribute using TLVs. It does not replace LOCAL_PREF; it participates later in best-path logic. The metric only makes sense inside a deliberately controlled AIGP domain.

Cisco IOS XR. Cisco ASR 9000/NCS documentation uses AIGP in RFC 3107 labeled-unicast designs where OSPF/LDP remains local and BGP carries remote prefix/label reachability. Total AIGP metric preserves accumulated core cost as next hops change across boundaries.

Juniper Junos. AIGP is disabled by default; a disabled neighbor silently discards received AIGP. Junos applies AIGP after LOCAL_PREF. If the resolving next hop carries AIGP, that distance contributes to interior cost. Junos can translate AIGP to MED in selected designs.

Field consequence. BGP and labels can remain Up while optimality silently changes because one boundary stopped carrying AIGP. Verify enablement, origination policy, next-hop-self, received metric, recursive tunnel cost, then best-path selection.

MEMORY ANCHOR: AS_PATH counts administrative hops; AIGP carries transport cost across a controlled multi-AS domain.
Active recall: Why non-transitive? Which attribute beats AIGP? What does disabled Junos do with a received AIGP?

  • Juniper — aigp (Protocols BGP) (Official, current): Default disabled and supported families.

OSPF SPF throttling and LSA throttling: protecting different convergence stages

Why this is hard. LSA generation/flooding and SPF calculation are separate. Throttling SPF does not directly rate-limit LSA origination; throttling LSA generation does not prevent SPF for LSAs already received.

Cisco IOS XE. timers throttle spf start hold max dynamically backs off: repeated changes double the interval until the maximum. Cisco separately exposes timers throttle lsa and timers lsa arrival. Current IOS XE 17.x allows 1–600000 ms for SPF values.

Juniper Junos. spf-options uses delay, rapid-runs, and holddown. Current defaults are 200 ms, 3 rapid runs, and 5000 ms. After the rapid-run budget is consumed, holddown prevents repeated CPU-intensive SPF work.

Arista EOS. EOS exposes initial, hold and maximum SPF delay behavior. The operational goal is the same as Cisco—react quickly to isolated events and back off during instability—but timer-reset semantics should be verified, not assumed identical.

Field consequence. BFD can detect a failure in tens of milliseconds while OSPF remains deep in throttle backoff. Check current SPF scheduling and last-SPF timestamps before blaming hardware programming.

MEMORY ANCHOR: LSA throttle controls how often change is advertised; SPF throttle controls how often topology is recomputed.
Vendor implementation sources

  • Cisco — Catalyst 9000 OSPFv3 Fast Convergence (Official, 2026): Separate LSA/SPF throttles.
  • Juniper — spf-options (Protocols OSPF) (Official, current): Defaults and ranges.
  • Arista — EOS User Manual — OSPF SPF Throttling (Official, 2026): EOS initial/hold/max SPF behavior.

MPLS TTL propagation: uniform versus pipe mode changes traceroute visibility

Why this is hard. MPLS has its own TTL, and operators choose whether IP and MPLS share one visible hop budget or behave like separate domains. The choice affects traceroute, ICMP and topology visibility without changing basic label forwarding.

Cisco. Default uniform behavior copies the decremented IP TTL into the MPLS label and later copies the remaining MPLS TTL back to IP. no mpls ip propagate-ttl gives the imposed label TTL 255 and prevents normal copy-back, hiding core hops from customer traceroute.

Juniper. Uniform is default; no-propagate-ttl enables pipe behavior. Global pipe mode uses TTL 255 on imposed labels. Junos documents a subtle copy-down case when the outer TTL is smaller than an inner value, and LDP-over-RSVP can inherit the RSVP tunnel's TTL semantics.

Field consequence. A traceroute that skips P routers does not prove the core is bypassed. Pair traceroute with LFIB/LSP state. TTL mode is a visibility policy, not an encryption or reachability mechanism.

MEMORY ANCHOR: Uniform lets IP TTL see through MPLS; pipe gives the MPLS tunnel its own hop budget.
Vendor implementation sources
  • Cisco — The Traceroute Command in MPLS (Official Support): Default propagation and no-propagate behavior.
  • Juniper — no-propagate-ttl (Official, current): Global pipe-mode behavior.
  • Juniper — MPLS TTL Propagation Flexibility for LDP LSPs (Official, current): LDP-specific and LDPoRSVP caveats.

BGP Route-Target Constraints: advertise VPN interest before sending VPN routes

Why this is hard. Route Targets decide VRF import, but without RTC a PE/RR may still receive every VPN route and discard most locally. RTC adds a preceding distribution stage: routers advertise the RTs they care about so irrelevant VPN NLRIs are not sent in the first place.

Mechanics. RFC 4684 defines RT-Constrain NLRI. Partial deployment is subtle: a speaker facing a peer that lacks RTC may advertise a default constraint on its behalf, effectively requesting everything and eroding scale savings.

Juniper. Junos supports BGP, static and proxy RTC. Static constraints reside in bgp.rtarget.0. Proxy RTC can infer membership for non-RTC peers, but automatic inference assumes symmetric import/export RTs; hub-and-spoke asymmetry can require static configuration.

Cisco IOS XR. In cited EVPN designs, address-family ipv4 rtfilter enables RTC; no separate EVPN-specific switch is required.

Field consequence. A route absent from the VRF may have been filtered before it ever reached the PE. Troubleshoot RTC membership → RR distribution → VPN table → RT import → RIB/FIB.

MEMORY ANCHOR: RT says “I import this.” RTC says “therefore send routes with this RT to me.”
Vendor implementation sources

  • Juniper — Route Target Filtering (Official, current): Static/BGP/proxy behavior and partial deployment.
  • Juniper — route-target-filter (Official CLI): bgp.rtarget.0 static constraints.
  • Cisco — NCS 5500 EVPN VPWS — RTC (Official IOS XR): ipv4 rtfilter enabling RTC.

PAN-OS maximum-prefix protection: maximum, threshold, and action are three separate ideas

Why this is hard. “Max-prefix” is often remembered as one hard number, but PAN-OS Advanced Routing separates the absolute maximum, a percentage threshold, and the action taken.

PAN-OS Advanced Routing. BGP Address Family Profiles expose Number Prefixes up to 4,294,967,295 with default 1,000. Threshold defaults to 100 percent. The action is Warning Only by default or Restart. Legacy virtual-router BGP exposes peer Max Prefixes from 1 to 100,000 or unlimited.

Operational consequence. A route leak can intentionally reset a healthy TCP/BGP session when Restart is configured. Correlate received-prefix count and system logs before diagnosing BFD or transport. Warning Only, conversely, can leave the control plane processing a huge leak while alarms fire.

ARE caveat. Current PAN-OS documentation notes that BGP update-groups can bypass a per-peer next-hop check in PAN-290712. A peer can continue to receive updates while its next-hop reachability is wrong. Prefix-count health and forwarding health are independent.

MEMORY ANCHOR: Maximum defines capacity; threshold defines when to react; action defines the reaction.
Vendor implementation sources

  • Palo Alto Networks — Configure BGP (Official, current): Legacy Max Prefixes.

U-APSD: WMM access categories can trigger and deliver independently

Why this is hard. U-APSD is not simply “power save on.” Specific WMM access categories can be trigger-enabled, delivery-enabled, both, or neither. A client sends an uplink trigger; the AP can then deliver multiple buffered downlink frames in a service period.

Cisco Catalyst 9800. IOS XE 26.1 says U-APSD activates automatically when WMM is enabled. show wireless client mac-address ... detail exposes WMM support, U-APSD support and per-AC flags such as BK(T/D), VI(T/D), VO(T/D). T means trigger; D means delivery.

Aruba/Juniper evidence. Aruba interoperability reports show that some WMM-capable clients support U-APSD while others do not. Juniper's Ascom i63 Mist report validates WMM prioritization and U-APSD separately. Client capability, not AP configuration alone, determines final behavior.

Field consequence. WMM enabled does not prove a voice client uses U-APSD. “Power Save OFF” in a snapshot means it is not currently sleeping; it does not negate support. Correlate capability, AC bitmap, current state, DTIM and latency/battery symptoms.

MEMORY ANCHOR: WMM classifies traffic; U-APSD uses selected WMM queues to decide what wakes the client and what the AP may deliver.

Scenario learning and field notes

AIGP boundary loss: BGP LU and labels stay Up but optimum path changes; verify AIGP enablement, origination, next-hop-self, received metric, recursion and best path. Reachability can survive loss of the cost signal.

BFD-fast/OSPF-slow: inspect LSA generation, throttle/backoff and last SPF before blaming FIB. Detection and recomputation use independent clocks.

Hidden MPLS core: traceroute can skip P routers in pipe mode while LFIB/LSP forwarding is healthy. Visibility is not reachability.

Missing VPN route: RTC membership may filter the route before the VRF sees it. Distribution precedes import.

PAN route leak: Restart action can intentionally flap a healthy peer. Protection policy can look like transport failure.

Voice battery: WMM support does not imply U-APSD support or correct T/D AC negotiation. QoS is not power-save negotiation.
