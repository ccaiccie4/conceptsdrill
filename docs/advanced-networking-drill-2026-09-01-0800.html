Beginner primer

ESI: identifies one Ethernet Segment attached to multiple EVPN PEs. DF: PE selected to forward BUM traffic toward an ES for a service. NSSA: OSPF area that injects externals as Type-7 LSAs. Route tag: policy metadata used to remember origin. SRGB: MPLS label block used to derive Prefix-SID labels. Adj-SID: usually a locally significant instruction for a specific adjacency. min-links: minimum bundled members required before an aggregate is considered usable.

Did You Know That?

1. EVPN multihoming — endpoint routes can stay while segment next-hop state changes

Why it is hard: Type-1, Type-2 and Type-4 routes coexist but solve different problems. Type-2 identifies MAC/IP endpoints. Type-4 advertises Ethernet Segment participation and contributes to DF election. Type-1 Ethernet A-D creates an Ethernet-Segment-level dependency that supports aliasing and mass withdrawal.

Mechanism: in all-active EVPN, remote PEs can use multiple next hops toward one ESI. Aliasing lets a remote PE use another eligible PE on the same ESI even if that PE did not originate a particular MAC route. On a PE/access failure, withdrawing the Type-1 A-D per-ES dependency lets remote PEs invalidate that PE for many MACs without waiting for individual Type-2 withdrawals.

Cisco: NX-OS uses Type-4 Ethernet Segment routes for DF election and split-horizon state. Catalyst 9000 documentation makes a critical distinction: DF/non-DF controls BUM forwarding toward the CE on a per-service basis; a non-DF is not an STP-blocked unicast link in all-active mode.

Juniper: Junos calls Type-1 A-D per-ES a mass-withdraw route. Dynamic List Next Hop removes only a failed PE element from a multi-element ESI next-hop object instead of rebuilding the entire object, reducing MAC churn. Junos defaults to RFC 7432 modulo/service-carving DF election and documents a default 3-second hold timer; supported preference-based election can be non-revertive.

Memory anchor: Type-4 chooses the BUM gatekeeper; Type-1 proves/withdraws segment reachability in bulk; Type-2 identifies endpoints.
Recall: Which route provides mass withdrawal? Why can non-DF still carry unicast? Why can Type-2 stay while traffic moves?

2. OSPF NSSA — P-bit and forwarding address form a translation contract

Why it is hard: “Type-7 becomes Type-5 at the ABR” omits conditions. RFC 3101 uses the P-bit for propagation intent. A translatable non-default Type-7 with P set needs a valid non-zero forwarding address. Translation copies that forwarding address into Type-5 so the translator need not become the data-plane next hop.

N-bit versus P-bit: N lives in Hello options and must agree for NSSA adjacency; when N is set, E must be clear. P lives in the Type-7 LSA and expresses whether the external may be propagated outside the NSSA. These are different state-machine boundaries.

Cisco: IOS XE uses RFC 3101 behavior by default and can provide RFC 1587 compatibility. Cisco documentation specifically calls out forwarding-address/P-bit refinements because older NSSA mental models can produce wrong translation expectations.

PAN-OS: Advanced Routing uses protocol-specific OSPF redistribution profiles with route maps that can match interface, address, next hop, path type, area and tag. That policy decides which routes become external OSPF information; RFC 3101 still controls Type-7 propagation semantics.

Memory anchor: N asks “are we NSSA neighbors?” P plus forwarding address asks “may this Type-7 escape, and where should traffic really go?”
Recall: Which bit is in Hellos? What two conditions make a non-default Type-7 translatable? What happens to the forwarding address?

3. Mutual redistribution — failure exposes the loop that preference was hiding

Why it is hard: two redistribution points can be stable while the native route is present. A copied route may already have boomeranged through another protocol but lose route selection. When the native route disappears, the feedback copy can suddenly win. The failure did not create the loop; it exposed it.

Reusable design: mark route origin at the first redistribution boundary and deny that origin on the return boundary. Administrative distance is local RIB preference, not end-to-end provenance; it cannot by itself stop copied information from propagating.

Cisco OSPF↔EIGRP: current Cisco guidance demonstrates tagging on the OSPF side and filtering tagged routes at the reverse redistribution point. Important caveat: EIGRP does not carry the same OSPF external tag semantic end to end, so place the marker where it actually survives.

PAN-OS: legacy Redistribution Profiles are ordered by priority, lower number first. Advanced Routing moves policy into protocol redistribution profiles plus route maps; BGP Redistribution Profiles can reference route maps for OSPF/static/connected imports.

HPE Aruba AOS-CX: OSPF redistribution commands accept an optional route map directly at the copy boundary, which is the right place for origin filtering.

Memory anchor: redistribution is information copying; every copied route needs provenance and a return filter.
Recall: Why can a loop be latent? Why is AD insufficient? Where should a route map be attached?

4. SR-MPLS — Prefix-SID and Adj-SID are both labels but have different scope

Why it is hard: a Prefix/Node SID index is normally interpreted domain-wide through each router's SRGB, while a normal Adj-SID is locally significant to the node advertising it and means “take this adjacency.” Copying an Adj-SID label as if every router owns the same instruction breaks segment lists.

Cisco IOS XR: prefix-sid index derives the label as SRGB base + index; absolute can specify a label. N identifies node semantics; n-flag-clear avoids claiming node semantics. explicit-null sets the E flag and disables PHP so the egress receives explicit-null. php-disable also prevents PHP but can retain the actual Prefix-SID label to the egress.

Juniper: OSPF source-packet-routing can retain adjacency-SID state across a flap; current CLI documentation gives an OSPF adjacency-segment hold-time default of 180000 ms, range 180000–900000 ms.

Arista EOS: current EOS exposes show isis segment-routing adjacency-segments including allocation pool, SID source and V/L/B flags, letting the engineer verify scope rather than infer it from a numeric label.

Memory anchor: Prefix-SID = reach a prefix/node; Adj-SID = at the owning node, take this link. Index is portable; absolute label realization depends on SRGB.
Recall: Why can the same index map to different labels? Who interprets a normal Adj-SID? How does explicit-null differ from PHP-disable?

5. LACP min-links and fallback individual solve opposite problems

Cisco min-links: port-channel min-links keeps an LACP aggregate inactive when fewer than the configured number of members are bundled. It is admission control for sufficient capacity/availability. max-bundle caps the number of active members at the opposite side of the range.

Arista fallback individual: port-channel lacp fallback individual waits for LACP; after the fallback timeout, members act as individual switchports with port-specific configuration until an LACP PDU is received. This is useful for PXE/bare-metal systems that start LACP only after boot, but dangerous if parallel standalone links can bridge and loop.

HPE Aruba: AOS-CX documents a case where BFD can report a LAG down during member failure even though healthy members remain and traffic subsequently rebalances. Physical-member state, LACP aggregator state, logical LAG state and BFD session state are separate objects with different failure timelines.

Memory anchor: min-links protects the bundle from being too small; fallback individual bypasses the bundle when LACP is absent.
Recall: What happens below min-links? What exactly occurs after Arista fallback timeout? Why can BFD and LAG disagree?

Scenario learning

EVPN: Type-2 remains after one access link fails. Check ESI → Type-1 A-D → Type-4/DF → remote next-hop list → Type-2. A retained endpoint route does not mean mass withdrawal failed.
NSSA: Type-7 exists inside the NSSA but no Type-5 appears. Check N/E Hello agreement, P-bit, forwarding address, translator state and backbone LSDB.
Redistribution: a WAN failure removes the native route and a re-imported copy wins. Trace origin→first redistribution→tag→receiving protocol→return redistribution→RIB/FIB. Fix provenance, not just metric.
SR: adding a copied Adj-SID breaks a policy. Verify SID owner/scope and place the owner's node SID before its local adjacency instruction if required.
LACP: PXE works on individual links but creates a pre-LACP loop. Inspect fallback, VLAN/STP and server bridging before LACP forms.
