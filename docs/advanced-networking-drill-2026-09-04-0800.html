Beginner primer

GSHUT is a BGP maintenance signal. End.DT is SRv6 decap plus table lookup; End.DX is decap plus cross-connect. RIB scale converts EIGRP protocol metric precision into an installable metric. Conditional advertisement advertises routes based on BGP-RIB conditions. OFDMA schedules Resource Units; TWT schedules client wake times.

Did You Know That?

BGP graceful shutdown — signal versus convergence

GSHUT is not a polite hard reset. Cisco, Junos and EOS use the well-known graceful-shutdown community so a maintenance path can be de-preferred while the session stays up long enough for alternatives to propagate. Cisco warns that a too-short drain interval or a manual clear ip bgp can defeat the drain procedure. Junos receiver behavior is enabled by default and normally lowers local preference to 0, but explicit import policy takes precedence over the implicit behavior. Seeing the community proves the signal reached the receiver; it does not prove an alternate exists, recursive NEXT_HOP is valid, or the FIB installed the alternative.

MEMORY ANCHOR: de-prefer first, teardown second; community is the request, forwarding change is the result.

SRv6 DT versus DX — transport versus service lookup

Cisco IOS XR defines End.DT4/DT6 as decapsulation followed by a VRF/table lookup, while End.DX4/DX6 decapsulate and cross-connect toward a specific CE/adjacency. Think per-VRF versus per-CE service semantics. Junos BGP SRv6 supports end-dt4-sid, end-dt6-sid and end-dt46-sid, plus newer micro-DT/non-default service SID options. A reachable locator proves transport to the node, not that the SID is bound to the correct VRF or CE. When outer IPv6 delivery works but the inner flow dies after decap, stop debugging the underlay and inspect endpoint behavior, SID-to-service binding, VRF route, CE adjacency and FIB.

MEMORY ANCHOR: DT = table; DX = cross-connect.

EIGRP wide metrics — protocol precision versus RIB representation

Cisco named-mode EIGRP uses 64-bit wide metrics; classic mode uses 32-bit calculations. Default K values remain K1=K3=1 and the others 0. The RIB consumes a smaller representation, so metric rib-scale converts the wide metric for installation. Changing the scale clears and reinstalls EIGRP RIB routes, so this is not cosmetic. Stub routing solves another problem: query scope. eigrp stub leak-map selectively advertises exceptions without changing DUAL's feasibility logic. Wide metrics answer “what does this path cost?”; stub/summarization answer “who must participate when the route goes Active?”

MEMORY ANCHOR: wide metric = protocol precision; RIB scale = installed representation; stub = query scope.

PAN-OS Advanced Routing — accept, advertise and install are separate gates

PAN-OS BGP Filtering Profiles can use distribute lists, prefix lists and route maps. Conditional advertisement uses Exist or Non-Exist route maps evaluated against the local BGP RIB; only Match is effective in those condition maps, so Set actions are ignored. Separately, Advanced Routing can apply a logical-router RIB Filter so a route accepted into the local BGP RIB is intentionally blocked from the global RIB. Troubleshoot peer/Adj-RIB-In → local BGP RIB → BGP filtering/conditional logic → logical-router RIB Filter → global RIB → FIB.

MEMORY ANCHOR: PAN-OS can filter acceptance, advertisement and installation independently.

Wi-Fi 6 TWT versus OFDMA — two different scheduling dimensions

OFDMA divides a channel into Resource Units so multiple stations can share a scheduled transmission opportunity. Target Wake Time negotiates when a station should wake, allowing longer sleep intervals and lower battery use. Aruba campus guidance recommends keeping TWT enabled for supported clients, while Aruba's Wi-Fi 6 reference covers uplink/downlink OFDMA. Juniper Mist Wi-Fi 6 APs support OFDMA and TWT, but 1024-QAM still needs high enough SNR. Strong RSSI does not prove TWT negotiation, low retries or efficient RU scheduling. For battery drain inspect TWT; for dense small-packet contention inspect OFDMA; for poor PHY rates inspect SNR/retries.

MEMORY ANCHOR: OFDMA schedules who shares spectrum now; TWT schedules when a station wakes later.

Scenario learning

GSHUT signal present, traffic not drained: verify effective local-pref, alternate route, recursive NEXT_HOP, RIB/FIB and counters. Do not stop at community presence.
SRv6 locator reachable, VPN drops after decap: verify DT/DX behavior, service SID, VRF/table or CE cross-connect. Underlay transport is already proven.
EIGRP metric changes after RIB scale: compare protocol wide metric with installed RIB metric before blaming DUAL.
PAN BGP route learned but not forwardable: inspect local BGP RIB, filtering profile, logical-router RIB Filter, global RIB and FIB.
Strong RSSI, IoT battery drain plus contention: treat TWT negotiation, OFDMA scheduling and RF quality as separate checks.

Protocol interactions and field notes

  • GSHUT plus NEXT_HOP recursion: a de-preferred path cannot drain to an unresolved alternate.
  • SRv6 plus BGP VPN: control plane advertises route/SID, endpoint behavior performs the service lookup.
  • EIGRP plus RIB: DUAL owns feasibility; RIB scale owns installed metric representation.
  • PAN BGP plus global RIB: a learned route can be intentionally unavailable to forwarding.
  • TWT plus OFDMA plus SNR: scheduling enhancements do not remove RF fundamentals.
