Did You Know That?

1. BGP Roles + OTC: relationship semantics move into OPEN and UPDATE

Why this is hard. Traditional leak prevention is manually maintained policy. RFC 9234 adds two independent safeguards. The BGP Role Capability is negotiated in OPEN and says what the eBGP relationship is. The OTC attribute rides UPDATEs and records that a route has crossed a provider/peer/route-server boundary and should subsequently travel only toward customers.

Mechanics. Valid pairs are Provider↔Customer, RS↔RS-Client and Peer↔Peer. If both peers advertise incompatible roles, OPEN is rejected with notification code 2/subcode 11. Strict mode can also reject a peer that sends no role capability. OTC is optional transitive, type 35, four octets. An OTC route received from a Customer or RS-Client is a leak and becomes ineligible. A compliant speaker receiving a route from Provider/Peer/RS without OTC can add OTC locally, so early adopters still gain protection.

Junos. Junos supports customer/provider/peer/route-server/route-server-client roles and automatic OTC handling for IPv4/IPv6 unicast. Per-prefix otc-local-role policy exists for exceptions; Juniper requires consistent ingress and egress policy. A genuinely complex one-session relationship is a poor fit for one fixed role.

MEMORY ANCHOR: Role answers “what is this neighbor?” OTC answers “where may this route go next?”

2. BGP PIC: pre-program the backup dependency before failure

Why this is hard. A backup path in BGP is not automatically fast convergence. Without PIC, a PE failure can force hundreds of thousands of prefix FIB entries to be rewritten. PIC changes the data structure: prefixes point at indirect next-hop objects containing primary and backup forwarding state, so failure repair touches the shared dependency rather than every prefix.

Core vs Edge. PIC Core protects a changed IGP/core path to the same remote BGP next hop. PIC Edge protects loss of the BGP next hop itself. Cisco recommends BFD for rapid edge failure detection and IGP FRR/TI-LFA for core path repair. A control-plane-only RR does not need PIC because PIC solves data-plane convergence.

Implementations. Cisco IOS XE requires a truly independent alternate and documents platform/scale restrictions. In RR-based VPN designs, unique RDs help keep different-PE paths distinct so the backup survives selection. Junos protect-core installs alternate VPN forwarding state visible through indirect-next-hop detail. Arista EOS PIC Edge pre-programs primary and backup paths; BGP status code b identifies a backup.

MEMORY ANCHOR: PIC is not “BGP computes faster.” It is “the FIB already knows the backup.”

3. LDP session protection: the link adjacency can die while the label session survives

Why this is hard. LDP link Hellos discover direct peers; targeted Hellos discover remote peers; TCP carries label mappings. Session protection creates a backup targeted adjacency while the direct link is healthy. If that link fails but another IP path still connects the routers, the link-Hello adjacency disappears while the original LDP session remains Established.

Cisco IOS XR. Session protection can automatically create targeted Hellos for protected link peers. In the cited NCS implementation the targeted relationship can maintain the session for an unlimited protection interval. The direct LFIB path can still be gone; session Up is not proof that the failed interface is usable.

Junos. Junos uses the same targeted-Hello concept and can retain the remote adjacency for a configured interval. strict-targeted-hellos is a separate control: it ignores targeted Hellos from neighbors that were not explicitly configured. Session protection and LDP-IGP synchronization solve different phases: protection avoids rebuilding the LDP session; synchronization prevents a recovered link becoming preferred before labels are ready.

MEMORY ANCHOR: remote discovery preserves control continuity; forwarding still follows the surviving IP/LFIB path.

4. EVPN-VXLAN local bias: source VTEP replaces the MPLS ESI-label split-horizon clue

Why this is hard. EVPN over MPLS can carry an ESI label to prevent traffic returning to the Ethernet Segment from which it originated. VXLAN has no MPLS ESI label, so all-active EVPN-VXLAN uses source-VTEP awareness instead.

Local bias. Multihomed PEs track the VTEP addresses of peers sharing an ESI. Ingress BUM can be locally replicated to orphan/other local segments and also sent into VXLAN. A peer leaf recognizes the outer source VTEP as belonging to the same multihoming group and suppresses sending the remote BUM packet back onto the source Ethernet Segment.

Cisco/Juniper. Cisco Nexus documentation makes the important distinction that DF election primarily controls BUM toward the multihomed ES; a non-DF can still decapsulate BUM for orphan/singly-homed local ports. Duplicate DF for one ES/VLAN risks duplicate frames/loops. Junos explicitly describes source-VTEP-IP local bias because VXLAN cannot use the MPLS ES label.

MEMORY ANCHOR: DF chooses the BUM gatekeeper; local bias prevents the returning copy from re-entering its source ES.

5. Wi-Fi 7 MLO: multi-link association is not the same as simultaneous multi-radio traffic

Why this is hard. MLO looks like wireless link aggregation but clients have different radio architectures. MLSR maintains several link contexts with one physical radio active at a time. eMLSR accelerates switching. NSTR multi-radio has simultaneous-use restrictions. STR-MLMR can truly transmit and receive simultaneously on multiple links.

Juniper Mist. Current guidance distinguishes link steering from link switching and explains MLSR/eMLSR/NSTR/STR. Many real clients negotiate two links yet do not transmit concurrently. Packet troubleshooting must distinguish the MLD MAC from per-link MAC identities.

Cisco. Catalyst 9800 IOS XE 26.1 documents MLSR, EMLSR and MLMR; MLO becomes available with 802.11be. Feature history matters: 17.18.1 added low-power MLO operation on specified CW9176/CW9178 APs.

HPE Aruba. AOS-10 documents MLO aggregation/failover but also current restrictions: some 7xx deployments require MLO disabled for 802.11r, AP-725 does not support MLO, and mesh can be pseudo-MLO rather than true multi-link. A Wi-Fi 7 logo therefore does not prove every mode/feature combination.

MEMORY ANCHOR: MLO creates multiple link identities; radio architecture determines whether they are concurrent, switchable, or standby.

6. PAN-OS ECMP: several equal-cost FIB members, one selected path per session

Why this is hard. PAN-OS does ECMP per session, not per packet. Equal-cost routes can be copied from RIB into FIB (up to four; default Max Path 2), then a load-balancing method chooses one member when a new session is created.

Algorithms. IP Modulo hashes source/destination IP. IP Hash can use source only and optionally ports plus hash seed. Balanced Round Robin evens session counts; Weighted Round Robin biases new sessions by configured link weight.

Overrides. Symmetric Return can override normal ECMP for return traffic so it leaves on the ingress-associated interface/next-hop state. PBF tracks a return-MAC table, with a same-subnet route-lookup exception. Strict Source Path solves a different problem: firewall-originated IKE/IPsec is pinned to the physical interface owning the source IP to satisfy upstream RPF/anti-spoof expectations.

Failure boundary. Two equal-cost routes in RIB do not prove two routes are copied into FIB; two FIB members do not mean an established session is packet-sprayed. Verify ECMP enablement → Max Path → FIB group → hash method → session egress → return/strict-source overrides.

MEMORY ANCHOR: ECMP is session selection; stateful return and firewall-originated traffic can intentionally override the ordinary hash.

Scenario learning

Provider route leaks to another provider: verify negotiated roles, strict mode, OTC value, export eligibility and leak counters. Role checks session semantics; OTC checks route history.
200k VPN routes converge slowly despite backup: verify the alternate is in FIB/indirect-next-hop PIC protection, not merely present in BGP.
Direct LDP link dies but session stays Up: verify targeted adjacency and alternate IP reachability, then LFIB; protected control state can hide the direct dataplane loss.
DF is correct but BUM duplicates: inspect ESI peer VTEPs and local-bias split horizon separately from Type-4/DF election.
MLO shows two links but one-link throughput: identify MLSR/eMLSR/NSTR/STR and observe actual per-link Tx/Rx rather than negotiated BSSIDs alone.
PAN ECMP return path surprises: check Max Path/FIB members, hash method, session-selected egress, Symmetric Return and Strict Source Path.

Protocol interactions

Roles + policy: RFC 9234 automates relationship validation but normal policy can still be stricter. PIC + BFD + IGP FRR: edge detection, edge repair and core repair are different jobs. LDP protection + IGP sync: preserve the session versus delay preference of a recovered unlabeled link. DF + local bias: choose BUM egress versus suppress reflected BUM. MLO + roaming: link switching inside one MLD is not AP roaming. ECMP + stateful firewall: return-path state can override a naive hash expectation.
