Did You Know That?

BGP LLGR — stale truth can outlive the session

RFC 9494 defines capability negotiation plus LLGR_STALE and NO_LLGR. LLGR stale paths are least-preferred and should not be propagated to peers that did not negotiate LLGR. LLGR ends at stale-time expiry or when refreshed routing and End-of-RIB processing complete.

Cisco IOS XR: BGP persistence can begin when ordinary GR ends or immediately if GR is not enabled. Current IOS XR documentation explicitly keeps LLGR stale paths least-preferred. Flexible BGP Persistence in 26.1.1 adds newer stale-time/propagation controls on selected hardware; that is an enhancement, not baseline RFC behavior.

Juniper: receiver mode is enabled by default unless ordinary GR receiver behavior is disabled. Restarter/stale-time support is family-specific; changing capability/stale-time may reset the session so the new capability can be negotiated in OPEN.

Field consequence: peer Down + stale route Present does not prove recursive next-hop, MPLS/SR tunnel, adjacency, or FIB validity. LLGR is safe only where forwarding can realistically survive longer than control connectivity.

MEMORY ANCHOR: GR preserves during restart; LLGR preserves across a much longer control outage. Longer stale lifetime demands stronger forwarding verification.
Recall: What marks stale? What opts out? What does session Down fail to prove?

RSVP-TE FRR — detour versus facility backup

RFC 4090 defines two local-repair models. One-to-one creates a detour LSP per protected LSP. Facility backup builds a bypass tunnel that can protect many compatible primaries. The PLR redirects traffic and the MP rejoins the primary. Facility backup commonly stacks an outer bypass label over the original protected-LSP label.

Cisco: the backup must avoid the protected link/node/SRLG and connect PLR to MP. A backup tunnel being Up does not prove a given primary requested or received protection; check RRO local-protection available/in-use state and association.

Juniper: enhanced facility protection is enabled by default on cited MX/PTX releases; disabling it also changes RSVP refresh behavior. Arista EOS 4.36.2F: exposes global/per-tunnel link/node protection and bypass optimization controls. A request for node protection is still only a request until usable repair state exists.

MEMORY ANCHOR: Detour state scales per primary LSP. Facility state is shared. Backup exists ≠ this primary is protected.

PWE3 Control Word versus PW Status TLV

The control word is dataplane; status TLV is control-plane. RFC 4385 uses a first nibble of zero so MPLS payload inspection does not mistake PW payload for IPv4/IPv6 and ECMP it incorrectly. Optional 16-bit sequencing detects out-of-order traffic; receivers drop disorder rather than reorder it.

Cisco: current Cisco 8000 documentation describes sequence 1–65535, control-word placement and fragmentation bits. The PW FEC C-bit/MTU/interface parameters must agree. RFC 4447: PW Status travels in LDP Notification messages; unsupported peers fall back to label-withdraw behavior. Juniper: pseudowire-status-tlv is per-connection and disabled by default in the cited reference.

Field consequence: transport LSP Up does not prove pseudowire Up. Conversely, sequence-drop counters can show a dataplane ordering fault while targeted LDP and PW status remain healthy.

MEMORY ANCHOR: Control Word describes each packet. PW Status describes the service.

OSPFv3 — IPv4 routes over IPv6 link-local control adjacency

RFC 5340 uses IPv6 link-local source addresses on ordinary OSPFv3 interfaces; the learned link-local neighbor address becomes next-hop information. Link-local addresses belong in Link-LSAs, not inter-area/external/NSSA/intra-area-prefix LSAs. Instance ID has link-local significance and can separate OSPFv3 communities on the same wire.

Cisco: IPv6 must be enabled on a link even when OSPFv3 is carrying IPv4 AF routes. AF-specific state ultimately installs into the corresponding RIB. Juniper: realms maintain separate neighbors/LSDB and still use IPv6 link-local Hellos/next hops; LDP synchronization is IPv4-only, so OSPFv3 uses it only in the IPv4 realm. PAN-OS: OSPFv3 relies on IPsec for authentication and current CLI exposes neighbor/LSDB views including scope link-local.

MEMORY ANCHOR: OSPFv3 can carry IPv4 reachability, but the adjacency still lives on IPv6 link-local plumbing.

WMM TSPEC/CAC — priority is not admission

WMM EDCA gives AC_VO a better contention opportunity. Admission Control separately decides whether another real-time stream may consume airtime. TSPEC is the client's traffic-stream request; reaching the CAC limit can reject new calls while preserving current calls.

Cisco 9800: WMM is required for CAC. ap dot11 5ghz cac voice acm enables voice admission. Current command reference lists multimedia max-bandwidth 5–85%, default 75%. TSPEC inactivity timeout can be processed or ignored; default is ignore.

Aruba: official interoperability outputs expose WMM, U-APSD and TSPEC-related values independently, reinforcing that QoS, power-save and admission are separate. Mist: DSCP→WMM mapping changes contention priority; Mist explicitly states WMM does not guarantee throughput.

MEMORY ANCHOR: EDCA asks who gets a better chance to transmit; CAC asks whether another stream gets admitted at all.

Scenario learning

LLGR stale blackhole: peer Down, stale route remains, traffic fails. Verify LLGR community/timer → recursive next-hop → transport tunnel → adjacency/FIB before trusting retention.
RSVP backup Up but primary unprotected: verify FAST_REROUTE request, PLR/MP, bypass constraints and RRO local-protection flags.
PW transport Up/service Down: inspect VC FEC/MTU/C-bit/PW Status/attachment circuit; inspect sequence counters separately.
OSPFv3 IPv4 AF Full but forwarding fails: link-local control is proven; AF-specific LSAs/RIB/FIB are not.
AC_VO but new calls rejected: queue priority can be healthy while CAC has reached its media budget.
